# Conception — `egbavou/vat-number`

- **Date :** 2026-10-21
- **Statut :** décisions validées une à une par l'utilisateur en session de conception
- **Implémentation :** Codex, à partir du plan qui suivra ce document

## 1. Objet et périmètre

1. **Valider hors ligne** les numéros de TVA : format et clé de contrôle.
   - les 27 pays de l'UE + `XI` (Irlande du Nord), avec la clé de contrôle ;
   - `GB`, `CH` et `NO`, en format seul.
2. **Vérifier en ligne**, de façon facultative, qu'un numéro existe, auprès de **VIES** (API REST de la Commission européenne, sans SOAP). VIES couvre l'UE-27 et XI.

**Hors périmètre :**
- les taux de TVA ;
- l'autoliquidation et tout calcul de facturation : ils restent dans l'application (aujourd'hui le `VatService` de Consumedias) ;
- le SIREN et le SIRET → `egbavou/france-business-id` ;
- la migration de Consumedias, qui sera un sujet séparé.

Ce package remplace la partie générique de `VatService` et la dépendance `dragonbe/vies`, abandonnée depuis 2024 et qui impose `ext-soap`.

## 3. Validation hors ligne

### 3.1 API

Tous les noms ci-dessous sont sous `Egbavou\VatNumber\`.

| Élément | Nom |
|---|---|
| Objet valeur (`final readonly`, `Stringable`) | `VatNumber` |
| Construction et contrôle | `isValid(string $input, ?string $country = null): bool`, `tryFrom(...)`, `from(...)` |
| Depuis un SIREN | `fromSiren(string\|\Stringable $siren): self` |
| Données (propriétés en lecture seule) | `->value` (`EL094014201`), `->prefix` (`EL`), `->number` (`094014201`), `->countryCode` (code ISO : `GR`) |
| Affichage | `format()` renvoie la forme compacte, identique à `->value` (il n'existe pas de format officiel) |
| Conversion en chaîne | `__toString()` renvoie `->value` |
| Exception | `InvalidIdentifierException extends \InvalidArgumentException`, propriété `->reason` |
| Raisons | enum `FailureReason` : `InvalidCharacters`, `InvalidLength`, `InvalidChecksum`, `UnknownCountryPrefix`, `MissingCountryPrefix`, `CountryMismatch` |

```php
VatNumber::from('FR44732829320');                // OK
VatNumber::from('fr 44 732 829 320')->value;     // 'FR44732829320'
VatNumber::from('44732829320', country: 'FR');   // OK
VatNumber::from('44732829320');                  // MissingCountryPrefix
VatNumber::from('BE0403170701', country: 'FR');  // CountryMismatch
VatNumber::from('GR094014201')->value;           // 'EL094014201'
VatNumber::from('CHE-116.281.710 MWST')->value;  // 'CHE116281710'
VatNumber::from('NO 974760673 MVA')->value;      // 'NO974760673'

VatNumber::fromSiren('732829320');               // VatNumber FR44732829320
VatNumber::fromSiren($siret->siren);             // objet Siren de france-business-id, sans en dépendre
VatNumber::fromSiren('732829321');               // InvalidChecksum (Luhn du SIREN revérifié)
```

### 3.2 Règles

Elles s'appliquent dans cet ordre. La première raison rencontrée est celle renvoyée.

1. **Nettoyage :**
   - on retire les espaces (y compris insécables), les points et les tirets ;
   - on retire les suffixes `MWST`, `TVA` et `IVA` (Suisse) et `MVA` (Norvège) ;
   - on passe en majuscules.
2. **Préfixe :**
   - Sans préfixe alphabétique et sans `country:` → `MissingCountryPrefix`.
   - Avec `country:` et sans préfixe, on préfixe avec le pays donné.
   - Avec les deux, s'ils diffèrent → `CountryMismatch`.
   - `GR` devient `EL`, en préfixe comme en `country:`.
   - Préfixe inconnu → `UnknownCountryPrefix`.
3. **Caractères**, longueur, puis **clé de contrôle**, selon la spécification officielle de chaque pays → `InvalidCharacters`, `InvalidLength`, `InvalidChecksum`.
4. **France :**
   - **Clé numérique :** `(12 + 3 × (SIREN mod 97)) mod 97`. Le SIREN contenu doit aussi passer Luhn.
   - **Anciennes clés alphanumériques :** acceptées selon l'algorithme publié.
5. **`fromSiren()` :** calcule la clé française. Il revérifie le SIREN (9 chiffres + Luhn) **sans dépendre** de `egbavou/france-business-id`.

**Sources des algorithmes.** On suit la spécification officielle de chaque pays ; le plan citera la source pour chacun. Les tests croisent nos résultats avec `dragonbe/vies`, en dépendance de développement seulement, et avec les jeux de test publics de python-stdnum. On ne copie pas de code sous licence LGPL.

## 4. Vérification en ligne (VIES)

### 4.1 API

| Élément | Nom |
|---|---|
| Checker | `VatNumberChecker::check(string\|VatNumber $input, ?string $country = null): VatNumberCheckResult` |
| Résultat (`final readonly`) | `VatNumberCheckResult` : `status`, `checkedAt`, `vatNumber` (`?VatNumber`, null si le format est invalide), `name` (`?string`), `address` (`?string`), `reference` (`?string`, l'accusé VIES), `unavailableReason` (`?UnavailableReason`), `registryErrorCode` (`?string`) |
| Statut | enum `CheckStatus` : `Found`, `NotFound`, `InvalidFormat`, `Unavailable` |
| Raison d'indisponibilité | enum *backed* `UnavailableReason`, aligné sur `egbavou/benin-business-id` : `NoSource`, `RegistryError`, `Transport`, `HttpStatus`, `InvalidJson`, `Schema` |

```php
$result = app(VatNumberChecker::class)->check('FR44732829320');
$result->status;     // CheckStatus::Found
$result->name;       // nom renvoyé par VIES, ou null
$result->address;    // texte brut, ou null
$result->reference;  // accusé VIES si un requester est configuré, sinon null
$result->checkedAt;  // date renvoyée par VIES
```

### 4.2 Comportement

`unavailableReason` vaut `null` sauf quand le statut est `Unavailable`. `registryErrorCode` vaut `null` sauf quand la raison est `RegistryError`. Ces deux champs ont été ajoutés le 2026-10-21 pour s'aligner sur `RccmCheckResult` du package Bénin.

| Situation | Statut | `unavailableReason` | `registryErrorCode` |
|---|---|---|---|
| Format invalide, sans appel réseau | `InvalidFormat` | `null` | `null` |
| GB, CH, NO (non couverts par VIES), sans appel réseau | `Unavailable` | `NoSource` | `null` |
| VIES répond par un code d'erreur (`MS_UNAVAILABLE`, `MS_MAX_CONCURRENT_REQ`, `GLOBAL_MAX_CONCURRENT_REQ`, `SERVICE_UNAVAILABLE`, `TIMEOUT`, `INVALID_INPUT`…) | `Unavailable` | `RegistryError` | le code exact, par exemple `MS_MAX_CONCURRENT_REQ` |
| Aucune réponse : erreur réseau, délai dépassé, exception PSR-18 | `Unavailable` | `Transport` | `null` |
| Réponse HTTP différente de 200, dont les 5xx | `Unavailable` | `HttpStatus` | `null` |
| Corps de réponse qui n'est pas du JSON | `Unavailable` | `InvalidJson` | `null` |
| JSON inattendu (champs absents ou d'un autre type) | `Unavailable` | `Schema` | `null` |
| Réponse « valide » | `Found` | `null` | `null` |
| Réponse « invalide » sans code d'erreur | `NotFound` | `null` | `null` |

Précisions sur ces cas :
- **Réponse VIES « valide » :** `Found`. Le nom et l'adresse sont rendus en **texte brut** : on retire les retours à la ligne superflus et `---` devient `null`. Pas de découpage en rue, code postal et ville.
- **Réponse VIES « invalide » confirmée :** `NotFound`.
- **Tous les cas `Unavailable` du tableau :**
  - **Aucune nouvelle tentative.** C'est l'application qui réessaie si elle le souhaite, en s'aidant de `unavailableReason` et de `registryErrorCode`.
  - **Jamais d'exception** dans ces cas.
- **Piège observé le 2026-10-21 :** pour un numéro valide, alors que la France répondait `MS_MAX_CONCURRENT_REQ`, l'endpoint `GET /ms/{pays}/vat/{numéro}` renvoyait `"isValid": false` avec un `userError` égal à `MS_MAX_CONCURRENT_REQ`. Un `false` accompagné d'une erreur ne doit **jamais** donner `NotFound`. Il faut des tests sur ce cas précis.
- **Accusé (« lettre recommandée ») :**
  - si `vat-number.vies.requester` est rempli (le numéro de TVA de l'entreprise qui vérifie), on l'envoie à VIES, qui renvoie un numéro d'accusé stocké dans `->reference` ;
  - sinon, `->reference` vaut `null`.
- **`checkedAt` :** la date renvoyée par VIES (celle de l'accusé), ou l'heure locale si VIES n'a pas répondu.
- **HTTP :** un `ClientInterface` PSR-18 et un `RequestFactoryInterface` / `StreamFactoryInterface` PSR-17 sont injectés. Sous Laravel, le service provider branche Guzzle automatiquement.
- **Endpoint et format exact des réponses :** à fixer dans le plan, après vérification sur l'API réelle. Les réponses enregistrées serviront de fixtures de test.

### 4.3 Configuration

## 5. Règles Laravel

Tous les noms ci-dessous sont sous `Egbavou\VatNumber\Laravel\`.

| Élément | Nom |
|---|---|
| Règle de format | `Rules\VatNumberRule` |
| Règle d'existence | `Rules\VatNumberExistsRule`, option `->failWhenUnavailable()` |
| Service provider | `VatNumberServiceProvider` |
| Traductions | `vat-number::validation.<raison>`, en anglais et en français |

```php
'vat_number' => ['required', new VatNumberRule(countryFrom: 'vat_country')],  // pays lu dans un autre champ
'vat_number' => ['required', new VatNumberRule(country: 'FR')],               // pays fixe
'vat_number' => ['required', new VatNumberRule],                              // numéro complet 'FR44…'

'vat_number' => ['required', new VatNumberExistsRule(countryFrom: 'vat_country')],
'vat_number' => ['required', (new VatNumberExistsRule)->failWhenUnavailable()],
```

- **`VatNumberExistsRule` :**
  - elle échoue sur `NotFound` et sur `InvalidFormat` ;
  - par défaut, elle **passe** sur `Unavailable` ; avec `failWhenUnavailable()`, elle échoue.
- **Lecture du pays :** `countryFrom` lit un autre champ du formulaire (`DataAwareRule`). Si ce champ est vide, la règle exige un numéro avec préfixe.
- **Valeur qui n'est pas une chaîne :** la règle échoue avec le message `invalid_characters`.
- **Valeur vide :** la règle n'échoue pas, c'est le rôle de `required`.
- **Messages :** un message par raison, via `$fail('vat-number::validation.<raison>')->translate()`. Ils se surchargent dans `lang/vendor/vat-number/{en,fr}/validation.php`.

## 7. Tests

- **Par pays :**
  - des numéros valides réels, avec leur source ;
  - des numéros invalides, un par raison possible ;
  - le cas `GR` vers `EL` ;
  - les suffixes CH et NO ;
  - les anciennes clés françaises alphanumériques.
- **Croisement :** comparer nos résultats à ceux de `dragonbe/vies` sur un jeu de numéros des 27 pays de l'UE + XI.
- **VIES**, avec un client HTTP simulé et des réponses réelles enregistrées :
  - les cas `Found`, `NotFound` et chaque erreur passagère ;
  - le piège `isValid: false` + `userError` ;
  - un délai dépassé et une réponse HTTP 5xx ;
  - avec et sans requester ;
  - `---` converti en `null` ;
  - GB, CH et NO sans appel réseau.
- **Pas d'appel réel à VIES dans la CI.** Un groupe de tests séparé, désactivé par défaut, peut interroger le vrai service.
- **Laravel :**
  - `countryFrom`, `country` et numéro complet ;
  - la règle d'existence par défaut et avec `failWhenUnavailable()` ;
  - les messages en anglais et en français ;
  - Testbench.
- **Sans Laravel :** le cœur et le checker fonctionnent sans `illuminate/*` installé.

## 8. Points remplis à la rédaction, à valider à la relecture

- `FailureReason` est un enum *backed* string, avec des valeurs en snake_case qui servent aussi de clés de traduction.
- Si VIES répond `INVALID_INPUT` alors que notre validation hors ligne est passée, le statut est `Unavailable` (avec `RegistryError` et le code `INVALID_INPUT`) et non `NotFound`. On ne peut pas conclure, et cela signale un écart de spécification à corriger.
- Le requester est découpé en code pays + numéro pour l'appel VIES. S'il n'est pas lui-même un numéro de l'UE ou de XI valide, il est ignoré et l'appel se fait sans accusé.
- Le constructeur de l'objet valeur est privé : on ne passe que par `from()`, `tryFrom()` et `fromSiren()`.
- Une classe par pays sous `Countries/`, regroupées derrière un registre interne et non public.
